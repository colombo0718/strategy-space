# 新手引導檢核

> 來源：2026-08-04 由「爛引導逼你查攻略」影片（遊戲狂人／差游部）拆解延伸，見
> `matrix-manager/meetings/`（若已寫會議紀錄則連結補上）。

## 核心判準

玩家喊「這遊戲引導太差」，本質是玩家不知道自己該去哪、該幹嘛。根源永遠是
**開發者跟玩家的心智模型對不上電波**——開發者同時怕玩家找不到路、又怕玩家太輕易找到路，
兩種焦慮互相拉扯，就是引導設計難的原因。

引導分兩種，同一款遊戲可以同時把兩種都做好或都做壞：
- **顯性引導（強引導）**：文字提示、路徑光點、小地圖標點、「按頭操作」。玩家煩，
  但留存率最高，網路遊戲常見的必要之惡。
- **隱性引導（弱引導）**：靠場景、音效、視覺語言讓玩家自己摸索出路，評判標準是
  **潤物細無聲**——玩家事後覺得是憑自己的聰明才智破解的，不是被牽著走。

## 排雷：三種引導失敗模式

上線前檢查遊戲裡的每個關鍵節點（開場、卡關熱點、隱藏機制）是否踩到以下任一種：

- [ ] **反直覺**：引導邏輯跟玩家當下的直覺方向相反（例如畫面暗示往前、正解卻要原路
      返回；玩家直覺推箱子爬梯子過關，正解卻要先拿到別的能力再回來）。
      → 檢查法：站在第一次接觸的玩家角度走一次，不能用「已經知道答案」的視角驗收。
- [ ] **差一步沒滿**：給了引導，但漏了最後一步「具體怎麼做」。玩家知道要去哪、
      不知道怎麼去；或給了觸發條件，卻沒給任何時間/地點線索去等待或尋找。
      → 檢查法：把引導拆成「知道目標」「知道路徑」「知道操作」三段，任一段空白都算沒過。
- [ ] **資訊缺失**：連基礎操作說明或關鍵機制存在與否都沒告訴玩家（隱藏連招、隱藏
      系統全靠玩家自行領悟；地圖高重複率導致玩家迷失方向）。
      → 檢查法：新玩家在無攻略情況下，是否連「這個機制存在」這件事都不知道。

## 立標：好的引導長什麼樣

- [ ] **視覺高亮先於文字**：可互動物件用顏色/材質做區隔（同類手法：破壞物上色），
      不要第一時間就跳文字說明。
- [ ] **開場動作一次教兩件事**：讓玩家的第一個操作同時學會「這個能打/能拿/能破壞」
      跟「這是核心技能」，不要用分開的教學畫面各自說明。
- [ ] **漸進解鎖、不要開局塞教程**：內容量大的遊戲，教學隨玩法解鎖分批給，
      不要求玩家一開場就做「閱讀理解」——大多數玩家不會讀大段文字。
      文字說明留給玩家主動想確認規則的時刻（例如局後復盤、暫停選單），
      不要打斷正在操作的玩家。
- [ ] **強引導不是恥辱**：教學/新手場本來就可以做全自動或高提示密度，
      深水區（進階機制、自由決策）再逐步拿掉輔助。段位式開鎖（家庭場→進階場→
      談判場之類）本身就是這個判準的實作。

## 唯一的驗收方法

以上都是設計原則，**真正抓得出卡關點的方法只有一個：找沒玩過的人實測、記錄他們
卡在哪、卡多久**。開發者對自己的遊戲永遠有盲區（連宮本茂都被自己兒子的卡關問倒過）。
自己人玩過、覺得順，不能算過關。

- [ ] 上線前至少找 1-2 位完全沒接觸過該專案的人試玩，全程不給提示、觀察卡關點
- [ ] 記錄「卡住的位置」與「卡住多久」，回頭比對是否落在上面三種失敗模式
- [ ] 神作也會在引導上翻車（薩爾達時之笛「迷失森林」靠音量大小引導、關音效的玩家
      直接卡關）——這不是自己專案能力不夠的證據，是所有引導設計都該持續測試的理由
